## Record and state contract (task 1.3)

**Ownership and storage.** The new library is one Home-owned, schema-versioned managed document indexed by `(owner_user_id, station_workspace_id, normalized AssistantProgramKey)`; use a lock + atomic replacement in Ori-managed storage (not inside source folders or an ordinary Home directory reference). **2.2 storage decision:** the document is `AssistantProgramState.ProjectLibrary` in the canonical Home envelope. Its presence is the authority marker, committed with the data and operation receipt by one `workspace.Store.Update`. There is no separate sidecar that can publish a marker ahead of a document. `FileStore` renames a synced 0600 temp file and fsyncs the parent directory; `SyncStore` writes the folder and SQLite mirrors sequentially, so a crash between them can leave them split. Library reads and writes compare the two documents, ignoring only serialization whitespace, and fail closed with `ErrMirrorDiverged` until operator reconciliation, rather than discarding a newer receipt. This is **not** a cross-store transaction or automatic repair. This marker on the exact Home switches that Home's portfolio **metadata authority** from the legacy Home `Portfolio.Projects` to the library, only on an explicit reviewed library initialization, never on GET, login, provider reinstall, or Home restart. On initialization, copy the existing explicitly edited linked-project fields with their exact `(link_id, project_workspace_id)`, revision and source into library entries once under a migration receipt. The old Home portfolio values/operation receipts remain an immutable compatibility/history snapshot; all subsequent old and new UI/API edits route through one library service. Legacy direct service writes must delegate or fail closed on initialized Homes, not silently diverge. An uninitialized Home continues using the existing portfolio service unchanged; incomplete initialization must fail closed or reconcile by the recorded input digest before the pointer is published. Revalidate the Home/link on every association; never change Home or link provenance, role bindings or project-private state. The store is inaccessible to generic Home file tools. Coordinate explicit Home trash/restore/removal with the store marker, preserving history as appropriate and blocking writes while absent. Task 2.2 proves inert reads, envelope restart, SQLite/file mirror round-trip/rollback and split detection, CAS/replay, corrupt record refusal and status gating. Reviewed initialization now copies saved legacy edits and exact linked IDs under one Home update/operation receipt; `Store.mutate` cannot initialize implicitly. `AssistantPortfolioService` delegates old Home metadata list/review/commit through an explicit managed-library adapter wired in `sessionhttp` after the authority switch. Without that adapter, direct service calls still fail closed; legacy handoff remains independently gated and fails closed on managed Homes until its group-4 policy path exists; `TestStore_LegacyReviewCannotCommitAcrossAuthoritySwitch` covers a review generated immediately before the switch. There is **no new public library initialization/scan/edit route yet**; only the existing Home portfolio field endpoints delegate to the canonical library after an internal explicit switch. `TestInitialize_*` checks exact-field copy, unedited-link defaults, stale review, replay, restart and failed mirror save. `TestPortfolioBridge_*` and the old HTTP portfolio review/commit regression cover mixed old/new edits, replay and restart after the switch; 2.11 must ensure restoring a removed Home cannot silently reactivate old root grants. The embedded document includes absolute root paths and must never be serialized into agent prompts or generic API responses; task 4.2 must recheck tool authorization and project only bounded safe fields.

JSON decoding refuses unknown fields and invalid sizes. Each record carries a schema version and `revision` for compare-and-swap; document write revision serializes cross-record changes. Timestamps are UTC and labeled by source, never used to infer a production stage.

**Distinct consequences:** a native-picker selection is a short-lived reference, not a durable grant; connecting a discovery root is reviewed Home-scoped metadata-only consent, optionally with *one* explicitly disclosed bounded scan. Each subsequent rescan/narrower follow-up is its own explicit action. The browser can send only server-issued root/catalog/link IDs, relative scope IDs from known records and bounded metadata strings, never a typed absolute/relative filesystem path.

## Shared cross-process workspace fence (implemented 2026-09-29; reconciliation still owner-reviewed)

**What exists now.** Every `FileStore` write of `workspace.json` holds a per-folder advisory `flock` (`<folder>/.workspace.lock`, `internal/workspace/store_fence{,_unix,_windows}.go`). The **primary's version is the only sequence** for a protected record (`WorkspaceFenceProtected`: `AssistantProgramState` or `AssistantProjectLink` present on the incoming record or either mirror): `SyncStore.Save` reads the primary under the folder lock and refuses a base version that no longer matches (`ErrStaleWorkspaceVersion`) *before* touching any mirror, then persists the primary through `VersionedSaver.SaveExpecting` — a single SQLite `UPDATE … WHERE id = ? AND version = ?` in `session.SQLiteStore.UpdateWorkspaceExpecting`, never a read followed by an unconditional update. The folder's own version is deliberately not a sequence: session handlers still write the folder directly (create, tag and portable-state syncs, backfills) without touching the primary, so the folder side instead requires the two mirrors to **agree on the protected envelope** (the Home-state comparator the library already uses plus a compacted library-document and full-link comparison); a Home or link that reached one mirror only is `ErrWorkspaceMirrorsDiverged` and no new write may resolve it. That comparison runs when the primary offers conditional saves (SQLite, which returns an independent before image); a pointer-sharing in-memory test primary is not compared because its record may already carry the update callback's mutation. A FileStore that is not mirrored (no SyncStore) keeps a strict on-disk version check for protected records, since all its writers share one version. Before the folder rename a durable journal (`<folder>/.workspace.journal.json`: operation ID, base and target primary version, SHA-256 of the exact folder bytes before and after) is written and synced; a failed primary write restores the exact previous folder bytes and closes the journal, a failed compensation leaves it in place, and a direct folder write of a protected record refuses while such a journal is pending. The generic `SQLiteStore.UpdateWorkspace` used by session-level handlers is conditional on the version the caller read whenever the stored row is protected, so a stale generic writer cannot overwrite a newer fenced Home either; ordinary rows keep their unconditional update. `projectlibrary.Store` maps a fence refusal to `ErrConflict` (reload and review again) and a mirror split to `ErrMirrorDiverged`.

**Restart classification (implemented for the folder/primary pair).** The next fenced write of a protected workspace reads any pending journal and both mirrors independently: exact after/after closes the journal and proceeds; exact before/before closes it and proceeds (the old consent is spent because the write must be reviewed again against the current revision); before/after or after/before is `reconcile_required` and refuses with the operation ID; anything else (a third value, a missing mirror) refuses as `ErrWorkspaceFenceUnknown`. The folder is identified by exact bytes and the primary by version; different representations are deliberately not treated as equal. `FileStore.RestoreMirrorRecord` is the only path that writes a folder record exactly as given and clears its journal; it has no HTTP route and is the primitive a separately owner-reviewed reconciliation (and the disposable drills) use. Neither mirror is ever chosen automatically.

**Evidence.** The opt-in contract `go test -tags music_crossprocess_fence_contract -short -race ./internal/projectlibrary -run '^TestCrossProcess' -count=3` now passes both schedules three times: a separate OS process saving a pre-queue Home through `SyncStore` is refused and both reopened mirrors keep the acknowledged queue (`/tmp/ori-music-crossprocess-fence-contract-green.log`; the red run before the fence is `/tmp/ori-music-crossprocess-fence-contract-red-before-fence.log`), and a second process running a real queue Skip whose callback read the Home before the parent's own Skip is refused with the fence's message, leaving exactly one skip receipt in both mirrors. `TestFileStoreFence_*` and `TestSyncStoreFence_*` in `internal/workspace` cover two independent folder handles, exact rollback and same-object retry, folder-ahead version drift, every restart phase of the journal (after folder write, after both writes, after rollback, third value) and a failed compensation under a read-only folder; `internal/session` covers the one-statement conditional update and the protected-only generic update. The default `projectlibrary`, `workspace` and `session` race suites pass with the existing split-mirror drills rewritten to restore mirrors exactly instead of through a bumping save.

Power-cut/WAL durability of the journal and both mirrors is not proven beyond fsync-and-rename. It also shows that mirror equality alone cannot detect an acknowledged write overwritten in both stores.

**Proposed primitive (not an existing API):** one shared, durable per-workspace write fence used by **every** mutator of a protected Home or split child (creator/link/unlink, queue, sessions, staffing, repair, generic workspace updates and lifecycle). Admission must atomically acquire a monotonically increasing SQLite epoch and an occupied operation slot for that exact workspace and owner, rejecting an occupied or `reconcile_required` slot. Before touching either mirror, durably journal the exact primary *and* folder before images/digests, intended per-store after images/digests, immutable identity/parent/link/provider evidence, review and operation IDs, and the epoch. An operation whose after image cannot be computed or bounded in advance must not enter the write phase; the proposed old-child role repair has a fixed after image, whereas a creator may need a separate, explicitly journaled child phase. A Home or child from another process must see the occupied fence and wait/refuse, not silently skip it. A stale fence is **not** a timeout lease; restart enters diagnosis, not a new writer. The existing claimed repair intent is not such a shared fence or an already-authorized write.

The active writer must recheck owner, exact original creator, consumed owner review, provider generation/installation epoch, full Home/child mirrors and no existing role bindings **after admission and before a first write**. Provider lifecycle operations must participate in a compatible fence or a provider change during the save remains an unfenced race; repeating an earlier provider read is not atomic. Folder persistence needs a cross-process local filesystem lock and per-workspace generation/epoch compare through its final durable rename; SQLite needs a conditional update/transaction on the old generation **and** occupied epoch with exactly one affected row, not a predicate on ID alone. The folder write and its pre-write state must be stable under that lock until the conditional primary write and terminal journal transition. `SyncStore.Save`'s current blind folder-first/compensate-from-snapshot implementation cannot serve as this primitive. If local filesystem locking or SQLite durability cannot be guaranteed on a particular storage/backend, explicitly refuse this path. Journal and result durability, including WAL `synchronous=NORMAL`, fsync/rename and restart semantics, require separate proof before claiming power-cut safety; do not infer it from successful `Save` calls.

Recovery reads **both independently reopened** mirrors and the durable journal/fence before any user-facing success, writer retry or staffer read. ## Library Manager notifications (PRD `library-manager-notifications`)

This is the first instance of Ori's proactive-work harness: a durable **signal**, a **bounded look** by one exact agent, **inert proposals with provenance**, **one review surface** with many navigation-only entry points, **truthful degradation**, and **feedback** that is counted but never auto-applied.

### Signal and deterministic digest (implemented)

`finishScan` writes `library_digest` into the Home document in the same fenced update that records a `complete` or `partial` scan, then publishes one `library.scan_completed` event (`workspace.LibraryScanCompleted`: Home, scan and root IDs, coverage, and counts only — no path, folder, file or project name). Failed, cancelled, interrupted and replayed scans publish nothing; reads, restarts and provider reinstalls never publish. The digest counts entries this scan observed (`projects`), created (`new`), materially changed (`updated`) and newly marked unavailable, plus a **persisted-state** setup split: with exactly one compatible installed blueprint for the Home's pinned provider, an unlinked available/ambiguous entry is `activatable` when an observed alternate has a supported extension, else `unsupported_format`. When that evidence is missing the digest carries `setup_note` and zero setup counts. It never reads a folder, file or folder owner, so a setup review still repeats every check. A newer completed scan replaces it; a disconnected root's digest is not current. `GET …/library/summary` (owner-Home only, no query string, no scan) returns the digest, the ready-suggestion count over the shelf's newest 20 rows, and the shelf route.

### Surfaces (implemented)

The Home map draws a navigation-only badge on a program Home's district header when something is ready (`activatable > 0` or ready suggestions); it takes its own line above the header row and world bounds reserve room for it. The cockpit reads summaries on refresh, on tab-visible (reused inside 30 s) and on back/forward return — never on a timer. `GET /api/action-center/library` derives one owner-scoped "Home libraries" card per such Home; cards are not opportunities and have no dismiss, snooze or resolve. Both open `/workspaces/<slug>/assistant#projectLibraryProposals`, where the shelf focuses its heading once it has rendered.

### Bounded Manager review turn (contract written before implementation; task 3.1)

- **Trigger.** Only `library.scan_completed`, delivered in-process. The event is a notification, never authority; the run re-reads the Home.
- **Authority.** The runtime-resolved local instance bound to the Home's required primary Home-scope role (`ManagerAuthority`, `boundManager`), live installed-provider evidence and mirror agreement — checked at run start and again by every tool call through the existing `authorizeManager`. The optional Sample Manager, an unbound or disabled instance, a global agent with the same name, or a foreign Home never qualifies.
- **Tool allowlist.** Exactly the four reads (`home_library_search`, `home_library_detail`, `home_library_sessions`, `home_library_handoff_receipts`) and the five inert proposal tools, built by the host's instance-bearing factory for that exact instance. Any other tool name returned by the model is refused without execution. There is no confirm, commit, scan, grant, activation, staffing, workspace, file or external tool.
- **Caps.** At most 3 proposals per scan (enforced inside the proposal's own fenced write, not only by the loop), a 60-second wall clock for the whole turn, a token budget (`library_manager_token_budget` in settings; default and maximum 20,000 — settings can only lower it), at most 6 model calls and 12 tool calls. Exceeding any cap ends the turn; proposals already saved remain.
- **Once per scan.** `proposal_runs[scan_id]` in the Home document is claimed through the fence with a deterministic operation key, so two events — including from two processes — produce exactly one receipt and at most one turn. Receipt states: `started`; `finished` (reason empty, `proposal_limit`, `time_limit`, `token_limit`, `step_limit` or `model_error` after a saved proposal); `skipped(<reason>)` for `no_manager`, `no_model`, `provider_unavailable`, `unavailable`, `superseded`, `model_error`, `time_limit` or `interrupted`. A skip is recorded before any model call. A run left `started` is closed as `skipped(interrupted)` by the startup sweep once it is older than the turn's deadline plus margin, and is never rerun automatically.
- **Prompt.** A fixed system instruction plus the digest counts only — no paths, file names or project titles. Everything the tools return stays untrusted data.
- **Provenance.** A proposal saved during the turn carries `scan_id`, `source: manager_model` and the model name, stamped inside the same fenced write. Chat-created proposals keep no provenance (shown as a Manager chat suggestion). Provenance is excluded from proposal digests, so existing proposals keep validating.
- **Dedupe.** During a turn, a proposal for the same entry and kind as a non-expired, not-stale saved proposal is refused (and does not count toward the cap).
- **Replay.** The turn is not a task run and creates no Task, workspace or agent record; the receipt is its replay record, and a replayed event returns the receipt without a model call.

**Implemented (2026-09-30).** `internal/projectlibrary/manager_run.go` holds the receipts (`claimProposalRun`, `finishProposalRun`, `CloseInterruptedProposalRuns`), `admitRunProposal` (hooked into all five proposal writes) and the bounded loop; `internal/server/library_manager_review.go` subscribes it in `initializeEventSystem`, builds the instance-bearing tools (`WorkspaceToolProvider` with `SetManagerRun`) and resolves the Manager's own tool-capable model from its Home-local agent settings (a CLI provider that cannot round-trip tool calls is `no_model`). The startup sweep runs once when the event system is wired. Evidence: the `TestManagerRun_*` suite (scripted model; caps, allowlist, prompt contents, authority loss mid-turn, concurrency across two FileStore handles, restart, supersession, forged receipts), the chat adapter check in `TestHomeLibraryTools_*`, and the tagged fence contract (3× green with the new fields). **Model behavior with a real provider is NOT RUN**; the sandboxed browser acceptance records `skipped(no_model)` and proves the tool contract through the direct `/tool` path.

### Dismissal, memory and feedback (implemented)

`POST …/library/proposals/{id}/dismiss` (strict JSON, `confirm`, idempotency key) marks one waiting suggestion dismissed and appends to `proposal_dismissals`, a list bounded to 256 and pruned past seven days, because the suggestion itself expires after a day. Dismissal is reductive and is allowed after provider or Manager loss (`unavailable`), but not once a suggestion was confirmed, went stale or expired. A scan-review proposal for a (project, kind) dismissed within seven days is refused with `ErrRecentlyDismissed`, which the model sees as the tool result. The owner's answers are counted per kind on the Home's assistant learning sidecar (`proposal_feedback`, once per suggestion via a bounded ID list) after the Home write that recorded them; counting is best effort and never becomes a prompt, toolbox change or learning candidate. Only next-action suggestions have a suggestion-specific confirm route, so "accepted" counts those only.

### Reads during an in-flight write (implemented)

A fenced Home write replaces the folder mirror and then the primary. A library read that lands between the two sees them disagree for a few milliseconds; the scan-review receipt written right after every scan made this visible as a shelf that briefly failed to load. `Store.readSnapshot` now retries a mirror split up to five times (about 150 ms in total) and then fails closed as before; it is never called inside a Home update callback. `TestReadSnapshot_WaitsOutAnInFlightWriteButStillRefusesAPersistentSplit` covers both outcomes.

### The proactive-work harness, as implemented here

1. **Signal:** `library.scan_completed`, published only after the fenced write that recorded the scan and its digest.
2. **Bounded look:** one turn per signal with the runtime-resolved instance, live provider evidence, a fixed read-and-propose allowlist, and caps on proposals, time, tokens, model calls and tool calls.
3. **Inert proposals with provenance:** stamped and capped inside their own fenced write; deduplicated against waiting suggestions and recent dismissals.
4. **One review surface, many entry points:** the Home's suggestions shelf; the map badge and the Action Center card only navigate to it.
5. **Truthful degradation:** the deterministic digest always runs; every skip records a visible reason.
6. **Feedback:** accept and dismiss counts shown to the owner, never fed back automatically.

A second source (a mission finding, a folder offer) reuses this by publishing its own path-free event, writing its own bounded receipt, and filing inert records that the same shelf-style surface and navigation-only entry points can show. Extract a shared package when that second source arrives (PRD open question 5).

**Still not established.** A real-provider run (model quality and token accounting per provider), a settings-page control for the token budget (settings.json only), crash-atomic feedback counting (a crash between the Home write and the sidecar write loses one count), and cross-process freshness of the badge beyond the cockpit's event-driven reads.
