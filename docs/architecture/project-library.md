## Record and state contract (task 1.3)

**Ownership and storage.** The new library is one Home-owned, schema-versioned managed document indexed by `(owner_user_id, station_workspace_id, normalized AssistantProgramKey)`; use a lock + atomic replacement in Ori-managed storage (not inside source folders or an ordinary Home directory reference). **2.2 storage decision:** the document is `AssistantProgramState.ProjectLibrary` in the canonical Home envelope. Its presence is the authority marker, committed with the data and operation receipt by one `workspace.Store.Update`. There is no separate sidecar that can publish a marker ahead of a document. `FileStore` renames a synced 0600 temp file and fsyncs the parent directory; `SyncStore` writes the folder and SQLite mirrors sequentially, so a crash between them can leave them split. Library reads and writes compare the two documents, ignoring only serialization whitespace, and fail closed with `ErrMirrorDiverged` until operator reconciliation, rather than discarding a newer receipt. This is **not** a cross-store transaction or automatic repair. This marker on the exact Home switches that Home's portfolio **metadata authority** from the legacy Home `Portfolio.Projects` to the library, only on an explicit reviewed library initialization, never on GET, login, provider reinstall, or Home restart. On initialization, copy the existing explicitly edited linked-project fields with their exact `(link_id, project_workspace_id)`, revision and source into library entries once under a migration receipt. The old Home portfolio values/operation receipts remain an immutable compatibility/history snapshot; all subsequent old and new UI/API edits route through one library service. Legacy direct service writes must delegate or fail closed on initialized Homes, not silently diverge. An uninitialized Home continues using the existing portfolio service unchanged; incomplete initialization must fail closed or reconcile by the recorded input digest before the pointer is published. Revalidate the Home/link on every association; never change Home or link provenance, role bindings or project-private state. The store is inaccessible to generic Home file tools. Coordinate explicit Home trash/restore/removal with the store marker, preserving history as appropriate and blocking writes while absent. Task 2.2 proves inert reads, envelope restart, SQLite/file mirror round-trip/rollback and split detection, CAS/replay, corrupt record refusal and status gating. Reviewed initialization now copies saved legacy edits and exact linked IDs under one Home update/operation receipt; `Store.mutate` cannot initialize implicitly. `AssistantPortfolioService` delegates old Home metadata list/review/commit through an explicit managed-library adapter wired in `sessionhttp` after the authority switch. Without that adapter, direct service calls still fail closed; legacy handoff remains independently gated and fails closed on managed Homes until its group-4 policy path exists; `TestStore_LegacyReviewCannotCommitAcrossAuthoritySwitch` covers a review generated immediately before the switch. There is **no new public library initialization/scan/edit route yet**; only the existing Home portfolio field endpoints delegate to the canonical library after an internal explicit switch. `TestInitialize_*` checks exact-field copy, unedited-link defaults, stale review, replay, restart and failed mirror save. `TestPortfolioBridge_*` and the old HTTP portfolio review/commit regression cover mixed old/new edits, replay and restart after the switch; 2.11 must ensure restoring a removed Home cannot silently reactivate old root grants. The embedded document includes absolute root paths and must never be serialized into agent prompts or generic API responses; task 4.2 must recheck tool authorization and project only bounded safe fields.

**Records (no browser-selected paths).** All IDs are random opaque stable values scoped by the document owner/Home key, not display names, positional indexes or mutable path hashes. JSON decoding refuses unknown fields and invalid sizes. Each record carries a schema version and `revision` for compare-and-swap; document write revision serializes cross-record changes. Timestamps are UTC and labeled by source, never used to infer a production stage.

## Consent, threat and race contract (task 1.4)

**Distinct consequences:** a native-picker selection is a short-lived reference, not a durable grant; connecting a discovery root is reviewed Home-scoped metadata-only consent, optionally with *one* explicitly disclosed bounded scan. Each subsequent rescan/narrower follow-up is its own explicit action. Connecting one exact child via the canonical project creator is a new reviewed consequence, with File-only as default and staffing separate. An agent's proposal is inert and cannot scan, issue tokens, accept reviews, call creator/commit, or access source files. File-only use requires neither REAPER running nor a model. The browser can send only server-issued root/catalog/link IDs, relative scope IDs from known records and bounded metadata strings, never a typed absolute/relative filesystem path.
