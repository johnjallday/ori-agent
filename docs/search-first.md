# Search one folder on this Mac

On a new local Mac installation, open Ori in the browser. Choose **Documents**, **Downloads**, or **Choose another folder…** to make a folder searchable. For Documents or Downloads, Ori asks for confirmation by folder name before indexing. Choose **Allow search** to continue, or **Cancel** to leave your sources unchanged. This is separate from macOS privacy permissions: macOS may also ask for access, but won’t necessarily prompt if access was already decided. Choosing your first folder also makes Files your starting page on a new installation. **Not now** goes to Home without confirming a workspace directory or completing Welcome. Canceling a folder dialog makes no choice at all.

If you've already set up Ori, use **Files** in the rail beside Home's workspace cockpit. The rail has two destinations, **Files** and **Map**, and there is no separate Tree toggle: Files is the tree. Visiting Files or **Map** does not change your starting page. Use the explicit starting-page button on the standalone search page (the **Manage search locations** link in Files' header) to change it. When Files is your starting page and a workspace exists, Ori opens Files in Home; before any workspace exists it opens the first-run page above. If setup is incomplete, the desk offers **Start or resume workspace setup** instead of promising a map. Once you're in Files, filename search runs locally: querying or selecting a folder never calls a model and doesn't require a Personal HQ.

## Search Files by name

Files has one box, **Search by name…**. Type part of a name: Ori finds workspaces, notes, tickets, chats, agents and stored files whose _names_ match, in every workspace, even ones you have not opened, and shows them in a **Results** tab beside the tree. On this Mac it also lists files from folders you made searchable, merged newest first with the rest and labelled with their folder. The tree is never narrowed by a search; **Show in tree** on a result opens its parents and focuses its row. Matching is by name only, ignores case, and never reads note text, ticket bodies or file contents. Results arrive 25 per kind with **More results**. If one kind could not be searched, the others still show and that kind says so with **Retry**.

Press **/** to focus the box, **Down** to walk the results, **Enter** to open one and **Esc** to clear. A file from a searchable folder is selected first; **Enter** again opens it in its reader and **Shift+Enter** reveals it in Finder. These are explicit desktop actions, as on the standalone page.

To search in one place only, open a row's menu and choose **Search in this workspace** (a group row says **Search in this group**) or, on a folder inside Files or Outputs, **Search in this folder**. A searchable linked folder offers the same. A chip beside the box reads `in <name>`; its ✕ takes it off and searches everywhere again. A workspace or group scope finds every kind inside it; a folder inside a workspace finds only files in that folder; a searchable linked folder asks only the filename index for that folder. Esc clears the term but leaves the chip.

The term is sent in a request body for each search and nowhere else. It is not in the address, browser storage, the remembered tree tabs, a log, or a request URL, and a result in a search-only folder is never stored as a tab. Away from the Mac that runs Ori, Files searches what is inside workspaces and says in one line that folders you made searchable are not searched here.

## Add a folder after workspace setup

On this Mac, choose Downloads, Documents or another local folder in Files. The **Explore** card opens right there: keep the folder name or give the workspace its own name, choose whether to make filenames searchable, then select **Create workspace**. There’s no template, model or agent to choose. The assistant’s **Explore a folder** offers the same card in the conversation. Use its separate hire option if you want an agent. **New Workspace** still offers advanced setup and uses the same folder selection and consent checks. Linking lets workspace tools read the original folder in place; **filename search** is a separate choice. It indexes names, locations and dates on this Mac, not file contents. Choosing or cancelling a folder does not create anything. Search consent does not hire an agent, send files to a model, start Filing or prepare Notes.

If the folder already has an eligible workspace, reuse it. Choose a workspace if more than one links to that folder. An older link may ask you to verify its current folder because its original disk identity was not recorded. If the folder already appears in Files by itself, use **Manage search locations → Connect to workspace** to keep its existing index. Nothing is converted on upgrade. If creation succeeds but the search connection fails, keep the workspace and choose the same folder again in Files to finish just that step.

## Search locations

Choose **All locations** or a folder in the **Search locations** sidebar (use **Search in** on narrow screens). The heading names the active location; the desk lists names, relative locations and modification dates newest first. **Add folder…** opens the folder controls. Expand **Manage search locations** below the results to check coverage, refresh or remove a grant. A search location alone is not a workspace or permission for an agent to read files. Ori indexes names, relative locations, modification dates and local identity metadata. It doesn't extract text, move files, hand their names to a model, or store your queries in note-search history. Directory access is limited to the selected local APFS folder. Private Ori roots, system folders, whole volumes and overlapping sources are refused. System privacy controls can still refuse a selection.

- Type a filename or part of one. When two names match, use the source, relative parent and date to tell them apart. Notes and headings are a separate scope in the search palette.
- Use the arrow keys to select a row. **Enter** requests the displayed reader for a supported document or media file; **Shift+Enter** requests Finder. Unsupported files offer Reveal rather than a launch association. These are explicit desktop actions, not permission for an agent to read the file. A moved, replaced or inaccessible result can no longer be opened from the old row.
- Results arrive in batches. **Partial** means some entries couldn't be mapped, not that there are no more files. Hidden/tooling directories, app bundles, symlinks, other mounts and flagged cloud placeholders are excluded. There are caps on traversal time, depth, entries and index size.
- There is no watcher. Returning to Search shows the saved index; use **Refresh** to map again. Refresh starts a new generation, so deleted or previously indexed files aren't counted as newly verified. If the original root is unavailable, reconnect it and refresh, or remove it and explicitly choose a new source.
- **Remove from search** forgets that grant and its current index. It keeps the workspace and its external folder link, tickets, notes, originals, other mapped folders, macOS privacy settings and historical backups. Unlinking a workspace also does not revoke an independent search grant. To reconnect them, review the folder again. Removing the last folder leaves an empty search desk. Resetting ordinary workspace setup does not create or revoke grants; deleting app records clears all search sources and results. Start Fresh resets the starting page as well.

The implementation uses fixed system document readers, not “your default app.” On the standalone page, when you switch to Map and back in the same tab, Ori can restore the term, location and still-valid selected copy. It checks the current index first, including later pages. A refreshed or revoked copy must be selected again. The local service keeps one short-lived descriptor per view and tab in memory, not a history of searches. Terms, names and paths do not travel in links, browser storage or the map's view state. New tabs start independently; don't rely on restoration across a reload, timeout or restart.

Files in Home keeps its own descriptor in the same short-lived memory, separate from the standalone page's: the term, the scope, the selected result and how many pages of each kind were loaded. Switching Files → Map → Files in a tab keeps the search as it was. Leaving the page and coming **Back** brings it back, asked again, so a result that has since been renamed or removed is simply not there; a scope whose workspace is gone brings back nothing rather than the same term in the wrong place. Away from the local Mac there is no descriptor and the term is simply cleared on leaving.

The headless demo disables all desktop effects; it cannot verify Finder, a reader, or an OS privacy prompt. Native acceptance requires a separate foreground Mac test account with synthetic files.
